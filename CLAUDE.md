# CLAUDE.md — Field Design System Assistant Guide

Key commands, structure and rules for Claude Code and other assistants working **on** the Field Design System. (For building apps **with** Field, see `docs/AGENTS.md`.)

---

## Commands

- **Typecheck monorepo**: `npm run typecheck`
- **Build all packages**: `npm run build` (tokens → react → manifest → showcase)
- **Dev server (docs site)**: `npm run dev`
- **Regenerate the component manifest**: `npm run docs:manifest`

---

## Codebase Architecture

- **`packages/tokens`**: `@sam.barfield/field-tokens` — primitives, themes, presets, `createTheme` / `createThemePair`, CSS/DTCG/TS exporters, Tailwind preset. Build emits `dist/tokens.css` and `dist/themes/*.css`.
- **`packages/react`**: `@sam.barfield/field-react` — components (`src/components`), theme engine (`src/theme`), shared hooks (`src/utils/hooks.ts`: focus trap, scroll lock, dismissable layers, anchored positioning, controllable state) and `src/styles/field.css`. Build prepends the default theme variables to `dist/styles/field.css`.
- **`apps/showcase`**: Vite docs site. `src/docs/guides.tsx` (guides), `src/docs/componentPages.ts` (component page prose), `src/docs/examples/<page>/*.tsx` (live examples, shown as source), `src/router.ts` (hash routes).
- **`docs/COMPONENT_MANIFEST.json`**: Generated by `scripts/generate-manifest.mjs` from the TypeScript source and JSDoc. Do not edit by hand.
- **`.agents/rules/component-lifecycle.md`**: Checklist for adding or changing components.

## Architecture Rules

1. **No raw colours or hard-coded spacing** in `field.css` or component styles: use `--field-*` tokens. Component sizes that consumers theme go through variables with defaults (e.g. `var(--field-btn-height-md, 36px)`); public variables and classes are listed in the Styling guide's "Public CSS API" section (changing them is breaking).
2. **Accessibility first**: prefer native elements (inputs, buttons); use the shared hooks for overlays (`useFocusTrap`, `useScrollLock`, `useDismissableLayer`) and `handleListKeyNavigation` for menus/lists. Everything must be keyboard operable.
3. **Portals**: popups render via `createPortal` with `usePortalThemeProps()` on the root (keeps theme vars for container scopes; `.field-layer` never paints a background) and `useAnchoredPosition` for placement.
4. **Polymorphic links**: interactive items support `asChild`, `as` and `href`; use `getInteractiveElementProps(tag, …)` so `<a>` never gets `type`/`disabled`.
5. **Controlled + uncontrolled**: use `useControllableState`; value-based `onChange` (except native wrappers `TextInput` / `TextArea`).
6. **ESM**: relative imports in `packages/*/src` must end in `.js` (Node ESM). Component files start with `'use client'`.
7. **Document props with JSDoc** on the props interface; then run `npm run docs:manifest`.
8. **Component synchronization**: when creating or altering components, follow `.agents/rules/component-lifecycle.md` (manifest, docs page + examples, `GEMINI.md` / `docs/AGENTS.md`).
